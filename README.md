# SubtitleMerger

批量把字幕合进视频：支持 MKV / MP4 输出、软字幕（内挂多轨）与硬字幕（烧录）、拖放添加、自动匹配视频与字幕、中文/日文等 Unicode 字幕自动转码，默认**不重新编码**视频。

## 快速开始

前提：

1. **Python 3.8+**（安装时勾选 *Add python.exe to PATH*）
2. **ffmpeg / ffprobe**（硬字幕需要带 libass 的版本）—— 本工具靠 ffmpeg 完成合并，未内置（单文件就有 200 MB 左右）

```bat
git clone https://github.com/Utpop/SubtitleMerger.git
cd SubtitleMerger

启动.bat
```

无第三方包依赖 —— Fluent 主题引擎 [sv-ttk](https://github.com/rdbende/Sun-Valley-ttk-theme) 已随仓库附带在 `vendor/`，缺失时自动回退到内置等效主题。

程序会自动在 PATH、程序目录、`C:\ffmpeg\bin` 等处查找 ffmpeg；找不到时点界面右上角「更改」手动指定，路径会被记住（存于 `%USERPROFILE%\.subtitle_merger.json`，同时记住上次的输出目录、容器、编码器等）。源码方式运行时整个目录可以整包复制到任意 Windows 电脑，不需要联网、不需要安装任何包。

## 功能

| 需求 | 支持情况 |
| --- | --- |
| 视频格式 | MP4、MKV、MOV、M4V、AVI、WMV、FLV 等 |
| 字幕格式 | SRT、ASS/SSA、SUP（图形字幕）、SUB、VTT |
| 批量处理 | 整个文件夹，可含子文件夹 |
| 自动匹配 | 按文件名智能匹配，阈值可调，支持 `.zh` / `.en` / `.jpn` 等语言后缀 |
| 拖放 | Windows 原生拖放，无需额外组件 |
| 软字幕 / 硬字幕 | 两种模式；硬字幕可选「叠加全部字幕轨」或「只烧录第一条」 |
| 输出容器 | MKV / MP4，也可「与源文件相同」 |
| 多字幕轨道 | 一个视频挂任意多条，可设语言、轨道名、默认轨、强制轨、顺序 |
| Unicode 字幕 | 自动检测 GBK / Big5 / Shift-JIS / UTF-16 等并转 UTF-8，中文日文不乱码 |
| 保留原视频编码 | 默认 `-c:v copy -c:a copy`，秒级完成，画质零损失 |
| 进度 | 逐文件实时显示进度、速度、剩余时间，另有总进度条 |
| 失败隔离 | 单个失败仅标记该行，其余继续；最后汇总完成/失败/跳过 |
| 输出校验 | 每个输出自动核对字幕轨、音轨、时长与数据完整性，异常标黄并写进报告 |

## 使用

```bat
启动.bat          :: 或 python subtitle_merger.py
```

1. **添加素材**：把视频、字幕或整个文件夹拖进窗口顶部的虚线框，或点「添加视频 / 添加字幕 / 添加文件夹」
2. **检查匹配**：列表里每行是一个视频，「字幕轨」列显示自动匹配到的字幕；双击某行可手动增删字幕、设置语言与默认轨
3. **设置输出**：选容器（MKV / MP4）、字幕方式（软 / 硬）、输出目录；需要和源文件放一起就点「同源文件」（不会覆盖原文件，同名自动加后缀）
4. **点「开始处理」**：实时看进度、速度、剩余时间；随时可「停止」
5. 完成后可「打开输出目录」或「导出报告」（CSV）

## 软字幕 vs 硬字幕

| | 软字幕（内挂） | 硬字幕（烧录） |
| --- | --- | --- |
| 速度 | 极快（不重编码，一个文件通常 1-3 秒） | 慢（必须重新编码视频） |
| 画质 | 无损 | 有损（取决于 CRF） |
| 可关闭 / 切换 | 可以，播放器里自由切换 | 不可以，画面已烧死 |
| 样式 | 保留 ASS 特效（MKV） | 由 libass 渲染，依赖系统字体 |
| 推荐场景 | 绝大多数情况 | 发短视频平台、手机相册、不支持字幕轨的播放器 |

> 硬字幕的中文字幕依赖系统字体。若渲染出方块字，说明 ffmpeg 没找到中文字体，建议改用软字幕，或把字体放到系统字体目录。

### 关于「不重新编码」

默认视频、音频都是 `copy`，只做封装（remux），所以速度极快、画质无损。但有三个格式限制需要知道：

- **MP4 容器的文本字幕必须转成 `mov_text`**（格式限制，与画质无关）；转 mov_text 时 ASS 特效样式会丢失，MKV 输出可完整保留
- **SUP / SUB 图形字幕无法放进 MP4**（MP4 不支持），程序会自动跳过并在日志里提示，这类字幕请选 MKV 输出
- 源视频是 VP9 / AV1 等编码时，输出到 MP4 可能需要重编码，此时把视频编码改成 libx264 即可

## 自动匹配规则

- 先规范化文件名：去掉扩展名、括号内容、分辨率/编码/来源等噪音词（1080p、x264、WEB-DL…），去掉语言后缀，只保留核心标题
- 完全一致 → 命中；前缀/包含关系 → 高置信度；否则用相似度，默认阈值 **0.72**（界面可调）
- 一个视频可同时挂多条字幕；匹配不上的字幕不会乱挂（列表底部会提示未匹配数量）
- 特殊命名可双击视频行手动指定

## 字幕编码处理

MKV 里的字幕轨不记录编码，播放器一律按 UTF-8 解析，所以 GBK / Big5 编码的老字幕直接内挂会变成乱码。程序会：

1. 检测原字幕编码（BOM、严格 UTF-8 解码、GB18030 / Big5 / Shift-JIS 评分）
2. 非 UTF-8 时自动转成 UTF-8 再合并（可关闭）
3. 同时按文件名里的语言标记（`.zh` `.en` `.jpn` `.cht`…）自动写入轨道语言

## 输出校验

每个任务转码成功后会自动校验输出文件（「输出」标签页里可关闭，默认开启）：

| 检查 | 能发现的问题 |
| --- | --- |
| 字幕轨数量 | 字幕其实没挂上、图形字幕被跳过后的数量不符 |
| 音轨数量 | 音轨在封装时丢失 |
| 视频流、编码 | 输出为空壳、重编码结果不是预期编码 |
| 时长对比 | 输出与源时长差异过大 |
| 数据完整性 | 文件被截断、容器损坏、无法解码 |
| 体积对比 | 纯封装模式下体积明显缩水（数据不全的信号） |

全部正常 → 状态列显示「完成（已校验）」；有异常 → 显示「完成（校验异常）」并整行标黄，日志逐条列出问题，报告里单独一列。注意：校验异常**不是**处理失败（文件已生成），只是提醒人工确认。

### 性能与稳定性

- **并发探测** —— 添加文件后 4 线程并行读取媒体信息，大目录首次加载更快；开始处理前会再核对一次
- **转码结果缓存** —— 同一份字幕被多个视频引用时只检测/转换一次
- **失败隔离** —— 单个任务失败只标记该行并记录原因；字幕文件读取失败也只跳过那一条轨
- **可随时停止** —— 正在运行的 ffmpeg 会被终止，已完成的输出保留
- **界面不阻塞** —— 所有探测与转码都在后台线程

## 打包成 exe

`打包成exe.py` 打出一个单文件 exe（约 12 MB，冷启动实测约 2 秒），产物在 `dist\`。**本仓库不含这个 exe** —— 构建产物，已被 `.gitignore` 排除。

exe 内置 Python 运行时、sv-ttk 主题与图标，**不内置 ffmpeg**（塞进去会让 exe 膨胀到 170 MB 且冷启动要几十秒），会自动使用本机的 ffmpeg。用 exe 分发时目标机器只需要有 ffmpeg；用源码分发则需要 Python 3.8+ 和 ffmpeg。

```

├── subtitle_merger.py   # 主程序（GUI）
├── core.py              # 核心：匹配、编码检测、命令构建、进度解析

└── app.ico              # 程序图标（多尺寸；想换图标替换同目录的 app.ico 即可）
```

## 常见问题

**Q：提示没有 ffmpeg？**
装 ffmpeg 并加入 PATH，或点界面右上角「浏览」选 `ffmpeg.exe`（会自动同目录找 ffprobe）。路径会被记住。

**Q：处理失败怎么排查？**
日志区会打印每条任务的 ffmpeg 命令和错误信息。常见原因：输出目录无写入权限、源文件损坏、MP4 装不下图形字幕、硬字幕遇到 libass 缺失。

**Q：双击 bat 一闪而过？**
改用 `调试启动.bat`，会保留控制台显示错误。

**Q：拖放没反应？**
极少数系统/权限组合下拖放会失效，程序会在拖放框下方提示，用「添加文件夹」按钮即可。
