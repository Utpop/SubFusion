# 04 · 替代方案、原因与交互差异

> 选型原则：**优先 WinUI 3 原生控件**。下表中标「原生」的条目表示直接用平台控件完成，没有引入第三方或自绘方案；
> 标「替代」的条目表示原生能力确实不足，才采用平台 API / 算法移植 / 第三方包，并逐项说明原因与影响。
> 所有 GUI 交互差异集中在第 3 节，均为有意为之并给出理由。

> C# 版改用系统原生 Fluent 2 资源，会跟随 Windows 的浅色/深色模式与强调色。这是用户允许的「视觉风格可自由重新设计」，
> 且属于原生控件方案，不是替代方案；影响是界面在深色模式下会变深，而业务功能与所有文案不变。

## 2. 替代方案逐项说明

### 2.1 控件 / 平台能力层

| # | 需求 | 为什么原生控件不满足 | 采用的替代 | 影响 |
| --- | --- | --- | --- | --- |
| S1 | 9 列可横向滚动的表格（原 `ttk.Treeview`） | Windows App SDK 基础控件集**没有原生 DataGrid / TreeView 表格控件**；`CommunityToolkit.WinUI` 的 `DataGrid` 是额外包且是重型虚拟表格，为避免再引入一个第三方 UI 包，选用基础控件组合 | `ListView.Header` 放表头 `Grid` + `ItemTemplate` 放同宽 9 列 `Grid`，外层 `ScrollViewer.HorizontalScrollBarVisibility=Auto`；`StateToBrushConverter` 按状态着色 | 列宽固定（与原版一致）、表头随内容一起横向滚动；**不支持用户拖动列宽/列排序**（原版 Treeview 也未开启这些能力，实际等价）。`MinWidth=1260` 使窄窗口出现横向滚动条，与原版一致（v1.1 起任务表高度按 `0.38*` 分配、最小 110 DIP，窄窗口下先压缩表格而不是挤掉设置区） |
| S2 | 窗口最小尺寸 `1120×800` | WinUI 3 `Window` / `AppWindow` **没有 `MinWidth` / `MinHeight` 属性**（只有 `Resize`，`OverlappedPresenter` 也不暴露最小尺寸） | `NativeWindowHelper.cs`：`comctl32.SetWindowSubclass` 拦截 `WM_GETMINMAXINFO`，填写 `MINMAXINFO.ptMinTrackSize` | 仅适用于 unpackaged Win32 窗口（本项目正是如此）；不影响最大化/多显示器；DPI 由系统换算，逻辑像素语义与原 Tk `minsize` 一致 |
| S3 | 文件对话框指定 `initialdir` 任意绝对路径 | WinUI 3 的 `FileOpenPicker` / `FolderPicker` / `FileSavePicker` **只接受 `PickerLocationId` 枚举**（文档库、桌面、计算机等）与 `SettingsIdentifier`，没有任意路径属性 | 保留 `SettingsIdentifier`（`SubtitleMerger.Files/Folders/Executable/Report`）让 Shell 记住上次目录；`InitialDir` 参数保留在 `IUiServices` 签名中并写进配置 `last_dir`，但不传给 picker | 首次打开落在系统默认位置，之后由 Shell 记住用户上次选择；**不会自动跳到配置的 `last_dir` / 输出目录**。这是 WinUI 原生 picker 的平台限制，其余文件选择行为完全等价 |
| S4 | 原 `dragdrop.py`（`ctypes` + `WM_DROPFILES`） | 那是为 Tk 窗口补 Win32 拖放消息的钩子；WinUI 3 已内建基于 `Windows.ApplicationModel.DataTransfer` 的拖放，继续用 `WM_DROPFILES` 反而会与 XAML 输入路由冲突 | 原生 `AllowDrop` + `DragEnter/DragOver/DragLeave/Drop` + `GetStorageItemsAsync()`；`DragOver` 设置 `AcceptedOperation=Copy` 与提示文案，拖入/拖出时切换虚线框颜色 | 不需要手动 `DragAcceptFiles` / 窗口句柄 / 反注册；支持一次拖入多个文件与文件夹；不再有「拖放组件不可用」分支（原生能力始终存在），按钮添加入口仍完整保留 |
| S5 | 原 `fluent.py` 的 DWM 圆角 / 标题栏配色 | `apply_window_effects` 直接对 Tk 的 HWND 调 DWM；WinUI 3 的窗口由系统合成器绘制，不暴露同样的自绘标题栏接口 | 由 WinUI 3 系统窗口样式提供圆角、阴影、标题栏；`app.manifest` 负责 DPI 与长路径 | 不再手工指定 `caption_color`、不再关闭 Mica（系统按主题决定）；视觉效果更贴合系统，业务无影响 |
| S6 | 原「设置页等高，切换标签不跳动」 | `Pivot` 的 `PivotItem` 本身按内容自适应高度，无「统一为最高页」属性 | `Pivot` 占根 Grid 的 `0.62*` 行（`MinHeight=250`）+ 每页 `ScrollViewer`；**v1.1 去掉了早期写死的 `Height="252"`** | 效果等价（切换不跳动）；固定高度在 1080p/125% 缩放下会让底部按钮栏被挤出窗口，改为按比例分配后，四种窗口尺寸实测「输出」页都能完整显示 |
| S7 | 原 `tk.Text` 日志（disabled 但可选中复制、自动滚到底） | `ListView` 项目不可整段选中复制；`TextBox` 虽可复制但滚动到底需处理焦点，且会变成可编辑控件 | `ScrollViewer` + `TextBlock`（`IsTextSelectionEnabled="True"`、`TextWrapping=NoWrap`、等宽字体）绑定 `MainViewModel.LogText`；`ScrollLogToEnd()` 用 `UpdateLayout()` + `ChangeView` 滚到末尾 | 保留「只读、可选中复制、自动滚动、时间戳、清空」全部行为；日志是整段字符串而非行集合，超长日志的渲染成本与原 `tk.Text` 同量级 |
| S8 | 行状态配色 tag | WinUI `ListView` 没有 Tk 的 `tag_configure` 概念 | `StateToBrushConverter`（`IValueConverter`，`ConverterParameter=Back/Fore`）+ `JobViewModel.StateTag` | 6 种配色的具体色值取自原版；新增 `HexToBrushConverter` 供 ffmpeg 状态圆点复用 |
| S9 | 模态字幕编辑对话框居中到父窗口、`grab_set` | `ContentDialog` 由 XAML 自动居中并自带模态遮罩，无 `transient/geometry/grab_set` | `ContentDialog`（`MaxWidth=1200`、内容 `Grid 1040×520`）+ `XamlRoot = Root.XamlRoot` | 尺寸/位置由系统决定，不再是 `900×580` 上移 1/3；`确定/取消/关闭` 语义一致 |

### 2.2 运行时 / 算法层（非 GUI 控件替代）

| # | 需求 | 为什么不能直接用 | 采用的替代 | 影响 |
| --- | --- | --- | --- | --- |
| S10 | `gb18030 / big5 / shift_jis / euc-jp / euc-kr / cp1252` 旧代码页 | .NET Core / .NET 8 默认只内置 UTF 系列与 Latin1，**不含这些旧代码页** | `System.Text.Encoding.CodePages 9.0.0` + `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)`（`EncodingService` 静态构造） | 编码检测打分、GBK→UTF-8 转码行为与 Python `codecs` 等价（自检 7 组编码用例通过）；发布目录多一个约 1 MB 的官方包 |
| S11 | `difflib.SequenceMatcher.ratio()`（`autojunk=True`） | .NET BCL 无 `difflib` 等价实现；用 Levenshtein 或普通 LCS 会导致 0.72 阈值下的匹配结果漂移 | `Core/Services/SequenceMatcher.cs` 逐行移植 `b2j`、`autojunk`（`n>=200` 且重复度 >1% 的 popular 元素剔除）、`find_longest_match`、`get_matching_blocks` 与相邻块合并；递归改显式栈避免深栈 | 与 Python 的 `ratio()` 数值一致（自检 13 组相似度用例通过）；无外部依赖 |
| S12 | `subprocess.run(..., stderr=STDOUT)` 合并流 | `ProcessStartInfo` 只能分别重定向 stdout / stderr，**没有把 stderr 合并进 stdout 的开关** | `ProcessUtil` 返回 `(Stdout, Stderr)`，能力检测/版本检测处用 `Stdout + Stderr` 拼接后做子串判断 | 仅影响 `-filters` / `-encoders` / `-version` 的子串检测（这些输出本来就在 stdout）；`run_ffmpeg` 的进度流与错误流本来就是分离的，行为不变 |
| S13 | `CREATE_NO_WINDOW` + `encoding="utf-8", errors="replace"` + `stdin=DEVNULL` | .NET 无 `creationflags` 概念 | `ProcessStartInfo.CreateNoWindow = true`；`StandardOutputEncoding/StandardErrorEncoding = UTF8Encoding(false, false)`；`RedirectStandardInput` 并在启动后 `Close()` | 不弹控制台窗口、乱码替换为 U+FFFD、ffmpeg 不会等待 stdin，行为等价 |
| S14 | 子进程超时 | .NET `Process.WaitForExitAsync` 无内置超时 | `Task.WhenAny(WaitForExitAsync, Task.Delay(timeout))`，超时 `Kill(entireProcessTree: true)` 并返回 `TimedOut=true`，由调用方按「探测失败/不误报」处理 | 与 Python 捕获 `TimeoutExpired` 后吞异常的策略一致；额外使用进程树终止，避免残留子进程 |
| S15 | `json.dump(ensure_ascii=False, indent=2)` + 保留未知键 | `JsonSerializer` 默认转义中文；反序列化为强类型 POCO 会丢弃未知键 | `System.Text.Json.Nodes.JsonObject` + `JsonSerializerOptions { WriteIndented=true, Encoder=UnsafeRelaxedJsonEscaping }`，UTF-8 无 BOM 写入 | 中文不转义、缩进 2、未知键原样保留并写回；与 Python 配置文件双向兼容 |
| S16 | `csv.writer`（UTF-8 BOM + CRLF + QUOTE_MINIMAL） | .NET BCL 无内置 CSV 写入器 | `MainViewModel.AppendCsvRow` 手写：含 `, " \r \n` 的字段加引号并把 `"` 转义为 `""`，行尾 `\r\n`；写文件时前置 `EF BB BF` | 字节格式与 Python `open(..., encoding="utf-8-sig", newline="")` + `csv.writer` 一致；9 列顺序/内容一致 |
| S17 | `ThreadPoolExecutor` / `as_completed` | .NET 用 `Task` 异步模型更自然，且需要与 `CancellationToken` 打通 | `SemaphoreSlim(workers)` 限流 + `Task.WhenAny` 按完成顺序回调；`CancellationTokenSource` 取消 | 并发上限、失败隔离、按完成顺序更新行、取消后停止派发 `job_done` 均等价；取消时响应更即时（见 D4） |
| S18 | `queue.Queue` + `root.after(120, _drain_queue)` | WinUI 的 UI 线程调度用 `DispatcherQueue`，不需要自建队列 | `IBatchEvents` 6 类事件 + `IUiServices.RunOnUiThread`（`HasThreadAccess` 时同步执行，否则 `TryEnqueue`） | 事件顺序保持一致；从固定 120 ms 轮询变为即时投递，界面反馈更快 |
| S19 | `threading.Event` 取消 + `proc.terminate()` | 原版只在**读到下一行 stdout** 时才检查取消，ffmpeg 长时间无输出时「停止」会卡住 | `CancellationTokenSource` + `FfmpegRunner` 注册 `cancelToken.Register(() => process.Kill(...))`，取消即杀进程 | 停止更可靠；已完成的输出文件保留、当前任务标记「已取消」，与原版一致 |
| S20 | `bundled_dir()`（PyInstaller `sys._MEIPASS`） | .NET 无 PyInstaller | `ToolLocator.BundledDir()` / `HereDir()` 均返回 `AppContext.BaseDirectory` | 单文件/普通发布下语义等价（资源目录 = exe 目录）；工具查找顺序其余 5 级完全一致 |
| S21 | `os.startfile` / `explorer /select,` | .NET 无 `os.startfile` | `Process.Start(new ProcessStartInfo("explorer.exe", path){UseShellExecute=true})`；异常同样吞掉 | 右键「打开视频所在文件夹」「打开输出文件」实际打开的仍是**所在目录**（原版这两处传的也是目录），行为一致 |
| S22 | `tempfile.mkdtemp(prefix="submerge_")` | .NET 无同名 API | `Path.Combine(Path.GetTempPath(), "submerge_" + Guid.NewGuid("N"))` + `Directory.CreateDirectory`；结束时 `Directory.Delete(recursive:true)` | 命名前缀、生命周期、清理时机一致 |
| S23 | Python `info = {}` 空 dict 表示「尚未探测」 | C# 的 `MediaInfo` 对象始终非 null，无法用空对象判断 | `MediaInfo.Probed` 布尔标记，`ProbeStreamsAsync` 成功末尾置 `true`；`EnsureProbedAsync` 用 `!j.Info.Probed` 判断 | 判定语义等价，仅为类型系统差异 |
| S24 | PyInstaller 单文件 exe | .NET 使用 `dotnet publish`；且 WinUI 3 的 XAML 编译产物默认**不进 publish 输出** | `SubtitleMerger.App.csproj` 增加 `IncludeXamlArtifactsInPublish` 目标，显式复制 `App.xbf`、`Views/*.xbf`、`SubtitleMerger.pri` | 首次发布实测缺这 4 个文件导致 exe 无法启动，补齐后 `--smoke` 通过；发布形态从「单文件 ~12 MB」变为「目录 ~155 MB」，但自带 .NET/WinUI 运行时，目标机零安装 |
| S25 | `CommunityToolkit.Mvvm` 版本 | `8.4.2` 在 WinUI 3 下对字段式 `[ObservableProperty]` 生成不兼容 AOT/CsWinRT 的代码，报 54 条 `MVVMTK0045` | 固定 `8.3.2` | 保留字段式写法、零警告；若未来升级需改为 partial 属性写法 |
| S26 | `ensure_tcl_env()` / Tcl 启动失败弹窗 | C# / WinUI 3 完全不依赖 Tcl/Tk | 直接移除 | 无功能损失；不会再出现「请安装完整版 Python（勾选 tcl/tk 组件）」这类提示 |
| S27 | 拖放初始化失败回退文案 | WinUI 原生拖放无需初始化钩子，不存在该失败路径 | 移除 `拖放组件不可用/拖放不可用` 文案与日志 `拖放初始化失败：%s`；三个「添加…」按钮常驻 | 用户永远有可用入口，提示更简洁 |
| S28 | `_selftest/` 静态样本素材 | C# 自检改为运行时用 ffmpeg 生成临时素材 | `SelfTest/Program.cs` 在临时目录生成 3 秒测试视频、SRT、GBK 字幕，结束即删 | 不再需要仓库里的二进制样本；自检可重复、无残留 |

## 3. 与原版不同的交互决策（逐条注明原因）

| # | 差异 | 原版行为 | C# 版行为 | 原因 | 影响 |
| --- | --- | --- | --- | --- | --- |
| D1 | 未选输出目录时的提示 | `start()` 第 1218 行的 `请先选择输出目录。` **不可达**：`_collect_options()` 已提前 `return None`，用户点「开始处理」后静默无反应 | 把该提示移到 `CollectOptions() == null` 分支，弹窗明确告知 | 原版是明显的可用性缺陷；保留「必须选目录」的业务约束，只把反馈补齐 | 用户能立刻知道缺什么，其余流程完全一致 |
| D2 | 字幕对话框双击移除 | `self.lst_sel.bind("<Double-1>", lambda e: self._remove)` **漏写调用**，双击无效果 | `SelectedList_DoubleTapped` 真正调用 `OnRemove` | 修复原版缺陷；「← 移除」按钮行为不变 | 多了一个可用的快捷操作，不改变数据结果 |
| D3 | 阈值越界 | 只捕获 `ValueError`（非数字）并重置 `0.72`；`ttk.Spinbox` 允许手动输入任意数字，输入 `5` 会通过校验导致「全部字幕不匹配」 | `NumberBox` 原生限制 `0.4..1.0`；`Rematch()` 另对 `NaN` 或越界值重置为 `0.72` | 原生 `NumberBox` 本就强制范围，补齐防御避免产生无意义状态 | 输入 `5` 会得到 `0.72` 而不是「全部不匹配」；正常输入行为一致 |
| D4 | 停止行为 | 取消标记只在 ffmpeg 输出下一行时被检查，长时间无输出时停止按钮可能无响应 | 取消即通过 `CancellationToken` 回调杀掉 ffmpeg | 保证「可随时停止」这条功能真实成立 | 停止更快；已生成文件保留、当前任务标「已取消」，与原版一致 |
| D5 | 创建输出目录失败 | `os.makedirs` 异常未捕获，会在后台/界面层抛出 | 捕获并弹窗 `无法创建输出目录：<原因>` | 把不可读的异常变成可操作的提示 | 多一条错误提示；不影响成功路径 |
| D6 | 窗口初始尺寸与位置 | `1220×900`，手工计算居中（`x=(sw-w)//2, y=(sh-h)//4`） | **v1.1 起**取 `DisplayArea.WorkArea` 的 92%（高度再留 88 px 余量），居中；工作区 `<1280×900` 时直接最大化；最小尺寸上限不超过工作区、高度下限 600 DIP | 用户反馈「默认尺寸很大、很多界面显示不全」：固定 `1480×980` 在 1080p + 125%/150% 缩放下会超出工作区，底部按钮栏被裁 | 默认窗口随屏幕自适应；大屏仍是全屏大小的窗口，小屏自动最大化，任何缩放下底部按钮都在窗口内 |
| D7 | 提示区形态 | `lbl_hint` 普通 Label，宽度随窗口自适应换行，黄色文字 | `InfoBar`（Warning、不可关闭） | 原生控件自带图标/语义色/深色模式适配 | 文案逐字一致；视觉从「黄字」变为「警告条」 |

## 4. 平台限制与已知约束（非缺陷，迁移后仍需知晓）

1. **运行平台**：C# 版为 `win-x64` / WinUI 3 unpackaged 应用，需要 Windows 10 1809+；原 Python 脚本理论上可跨平台运行 Tk（但 `dragdrop.py`、`CREATE_NO_WINDOW` 已是 Windows 特化）。
2. **ffmpeg 仍不内置**：与 PyInstaller 版一致，运行时需要本机 ffmpeg/ffprobe；查找顺序、配置键、环境变量完全一致。
3. **文件选择器 initialdir**：见 S3，属于 WinUI 原生 picker 的硬限制。
4. **发布形态**：目录而非单文件；`dist/SubtitleMerger/` 需整体拷贝，不能只拷 exe（含 `.xbf`/`.pri`/运行时 DLL）。
5. **原版固有行为被等价保留**（未「顺手修好」，避免破坏兼容性）：`container="same"` + 源为 MP4 时仍用 `-c:s copy`；硬字幕 `plan.vcodec` 仍为 `copy` 因而不校验实际编码；`forced` 覆盖 `default`；`overwrite` 不持久化；带连字符的语言键永不被命中。
6. **配置文件双向兼容**：C# 版直接读取原 Python 版写出的 `%USERPROFILE%\.subtitle_merger.json`，Python 版也能读 C# 写出的配置（键名、类型、字符串化数值一致）。

## 5. 影响总结

- **业务行为**：0 项缺失。191 个功能点中，仅 D1–D5 属于对原版缺陷/平台限制的显式修正，且都不改变成功路径的输出结果。
- **视觉与交互**：全部重设计为 WinUI 3 原生 Fluent 2 风格，覆盖原版全部 26 个交互入口；新增 2 个便利点（日志可选中复制保留、双击移除生效），移除 1 个无用分支（拖放初始化失败）。
- **依赖变化**：删除 Python 解释器、Tcl/Tk、`vendor/sv_ttk`、`ctypes` 钩子；新增 .NET 8 / Windows App SDK 2.6.5 / CommunityToolkit.Mvvm 8.3.2 / System.Text.Encoding.CodePages 9.0.0。
- **验收**：见 [05 · 迁移与验证说明](05-迁移与验证说明.md)。
