### 1.1 为什么要拆三个项目

| 决策 | 理由 |
| --- | --- |
| `Core` 独立为 `net8.0` 类库 | 原 `core.py` 自身就声明「不依赖任何 GUI 组件」。把它隔离出来后，GUI 与自检程序共享同一份业务逻辑，避免出现「测试用的是另一份实现」的假等价；同时 `Core` 不引用 WinRT 类型，可在非 Windows App SDK 环境下编译与调试。 |
| `App` 单独引用 `Core` | WinUI 3 需要 `net8.0-windows10.0.19041.0` + `RuntimeIdentifier=win-x64` + Windows App SDK 运行时；这些约束不应污染业务层。 |
| `SelfTest` 单独引用 `Core` | 迁移验收需要「把 Python 版算出的结果当基准逐项比对」+「真实跑 ffmpeg」两条通道，控制台程序最适合放进自动化流程，且能早于 GUI 完成验证。 |
| 采用轻 MVVM（非完整框架） | 原 `App` 类把状态、控件、后台线程、消息泵揉在一起（1768 行）。拆分后：`MainViewModel` 持有全部状态与命令且**不引用任何 WinUI/WinRT 类型**（只依赖 `IUiServices` 窄接口），`MainWindow` 只管窗口外壳与原生平台能力。这样既能用 `CommunityToolkit.Mvvm` 的 `[ObservableProperty]`/`[RelayCommand]` 省掉样板代码，又不需要引入导航服务、DI 容器等原版没有的复杂度。 |
| `IBatchEvents` 回调接口 | 原版用 `queue.Queue` + `root.after(120, _drain_queue)` 把后台线程结果泵回 UI。C# 版由 `BatchProcessor` 通过 `IBatchEvents` 发出 6 类事件（`Log / JobUpdate / Progress / JobDone / AllDone / Fatal`），`MainViewModel` 统一用 `IUiServices.RunOnUiThread` 投递到 `DispatcherQueue`。职责等价，但去掉了 120 ms 轮询延迟。 |

### 1.2 线程模型

| 原 Python | C# |
| --- | --- |
| `threading.Thread`（能力检测、探测、批量派发） | `Task` / `async-await` |
| `ThreadPoolExecutor(max_workers=workers)` | `SemaphoreSlim(workers)` + `Task.WhenAny` 按完成顺序回调 |
| `queue.Queue` + 120 ms 轮询 | `DispatcherQueue.TryEnqueue` 即时投递 |
| `threading.Event` 取消 | `CancellationTokenSource`；`FfmpegRunner` 注册回调立即 `Kill` 子进程 |
| `threading.Thread` 读 stderr | `Task.Run` 异步读 `StandardError`，环形缓冲加锁保护 |
| `_UTF8_CACHE` 普通 dict（GIL 保护） | `ConcurrentDictionary` |

## 3. 依赖清单

### 3.1 开发环境

| 依赖 | 版本（本次验证环境） | 用途 |
| --- | --- | --- |
| .NET SDK | `9.0.320` / `10.0.302` / `10.0.403` 均可，工程目标 `net8.0` | 编译三个项目 |
| Windows SDK | `10.0.26100.0`（工程 `TargetPlatformMinVersion=10.0.17763.0`） | WinUI 3 编译 |
| Visual Studio 2022（可选） | 已安装 | 打开 `.sln` / XAML 设计器 |
| NuGet | nuget.org 可访问 | 还原包 |

### 3.2 NuGet 包

| 项目 | 包 | 版本 | 用途 |
| --- | --- | --- | --- |
| `Core` | `System.Text.Encoding.CodePages` | `9.0.0` | .NET Core 默认不含 `GB18030 / Big5 / Shift-JIS / EUC-JP / EUC-KR / cp1252`，注册 `CodePagesEncodingProvider.Instance` 后才能等价复现原版编码检测 |
| `App` | `Microsoft.WindowsAppSDK` | `2.6.5` | WinUI 3 控件与 Windows App SDK 运行时 |
| `App` | `CommunityToolkit.Mvvm` | **固定 `8.3.2`** | `[ObservableProperty]` / `[RelayCommand]`；`8.4.2` 在 WinUI 3 场景会对字段式可观察属性报 54 条 `MVVMTK0045`（AOT/CsWinRT 不兼容），故固定 8.3.2 |
| `SelfTest` | 无第三方包 | — | 仅引用 `Core` 与 BCL |

### 3.3 运行时外部依赖

| 依赖 | 是否内置 | 说明 |
| --- | --- | --- |
| `ffmpeg` | **否**（与原版一致） | 需带 `libass`（硬字幕）、`libx264`；按 `配置 → 环境变量 → 程序目录/bin → PATH → C:/ffmpeg/bin 等` 顺序查找 |
| `ffprobe` | **否** | 同上，选择 ffmpeg 时自动尝试同目录 `ffprobe.exe` |
| Windows App SDK 运行时 | **是**（`WindowsAppSDKSelfContained=true`） | 发布目录自带全部运行时 DLL，目标机无需预装、无需 MSIX 安装 |
| .NET 8 运行时 | **是**（`SelfContained` 由 WinUI 发布链带入 `win-x64` 运行时） | 发布目录可直接运行 |
| 操作系统 | Windows 10 1809（build 17763）+ / Windows 11，`x64` | 由 `TargetPlatformMinVersion` 与 `RuntimeIdentifier` 决定 |

## 4. 构建与运行

```bash
# 4.1 还原 + 构建整个解决方案（推荐）
dotnet build SubtitleMerger.sln -c Release

# 4.2 运行 GUI（开发调试，控制台可见输出）
dotnet run --project src/SubtitleMerger.App/SubtitleMerger.App.csproj

# 4.3 运行自检（A 逻辑等价 + B ffmpeg 端到端）
dotnet run --project src/SubtitleMerger.SelfTest/SubtitleMerger.SelfTest.csproj -c Release
# 只跑纯逻辑比对、跳过 ffmpeg：
dotnet run --project src/SubtitleMerger.SelfTest/SubtitleMerger.SelfTest.csproj -- --skip-e2e

# 4.4 发布可直接双击运行的 unpackaged 目录
dotnet publish src/SubtitleMerger.App/SubtitleMerger.App.csproj -c Release -o dist/SubtitleMerger
# 产物：dist/SubtitleMerger/SubtitleMerger.exe（整个目录约 155 MB）
```

### 4.1 关键工程属性

| 属性 | 值 | 原因 |
| --- | --- | --- |
| `TargetFramework`（App） | `net8.0-windows10.0.19041.0` | WinUI 3 最低要求 |
| `TargetPlatformMinVersion` | `10.0.17763.0` | 兼容 Windows 10 1809 |
| `RuntimeIdentifier` | `win-x64` | 与原版同为 Windows x64 桌面程序 |
| `WindowsPackageType` | `None` | **unpackaged**：不需要 MSIX 打包/签名，双击 exe 即用 |
| `WindowsAppSDKSelfContained` | `true` | 自带 Windows App SDK 运行时，目标机零安装 |
| `TreatWarningsAsErrors` | `true`（Core / App） | 保证交付代码零警告 |
| `ApplicationManifest` | `app.manifest` | DPI PerMonitorV2 + 长路径支持 |

### 4.2 发布补齐目标（必须）

WinUI 3 的 XAML 编译产物（`.xbf`）与资源索引（`.pri`）默认只进入 `build` 输出，**`dotnet publish` 不会自动复制**，发布目录缺它们时 exe 无法启动。因此 `SubtitleMerger.App.csproj` 中增加了 `IncludeXamlArtifactsInPublish` 目标（`AfterTargets="ComputeFilesToPublish"`），显式把 4 个文件加入发布清单：

```
App.xbf · Views/MainWindow.xbf · Views/SubtitleTrackDialog.xbf · SubtitleMerger.pri
```

这是本次迁移实测踩到并修复的问题；发布后务必执行 `--smoke` 验证（见 [05](05-迁移与验证说明.md)）。

### 4.3 `--smoke` 启动钩子

`App/App.xaml.cs` 在 `OnLaunched` 里检测 `--smoke` 参数：窗口成功创建并激活 1.5 秒后写出 `%TMP%/subtitle_merger_smoke.txt` 并以退出码 0 退出。用于无人工干预地验证 XAML 资源加载与主窗口构造；**正常双击运行不传该参数，完全不影响业务**。

| 层次 | 手段 | 结果 |

## 6. 与原版工程形态的差异概览

| 维度 | Python 版 | C# 版 |
| --- | --- | --- |
| 入口 | `启动.bat` → `python subtitle_merger.py` | `SubtitleMerger.exe` / `dotnet run` |
| 打包 | PyInstaller `--onefile`（约 12 MB，不含 ffmpeg） | `dotnet publish` 目录（约 155 MB，自带 WinUI/.NET 运行时，仍不含 ffmpeg） |
| 主题 | 自带 `vendor/sv_ttk` + `fluent.py` 自绘控件 | `XamlControlsResources`（Fluent 2，系统原生） |
| 拖放 | `ctypes` 注册 `WM_DROPFILES` | WinUI `DragEnter/DragOver/Drop` 事件 |
| 配置文件 | `%USERPROFILE%\.subtitle_merger.json` | **完全相同**，键名/类型/格式双向兼容 |
| 外部工具 | ffmpeg / ffprobe | **完全相同**，查找顺序一致 |
| 测试 | 无自动化自检 | `SelfTest` 206 项 + `--smoke` GUI 冒烟 |
